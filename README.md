# Облачный контроль

Решение кейса «Спутникс» — **алгоритм искусственного интеллекта для распознавания облачности на спутниковом снимке** (Sk Challenge 2026 Kids, возраст 14+).

Программа получает папку со снимками, для каждого считает процент облачности, удаляет снимки с облачностью выше 75 % и выдаёт оператору сообщение: имя сохранённого файла, процент облачности, имя удалённого файла.

Объяснение для учеников — в файле **[GUIDE_RU.md](GUIDE_RU.md)**. Здесь — запуск, устройство проекта и заметки для преподавателя.

## Быстрый старт

Нужен Python 3.10 или новее.

**Windows:** дважды щёлкните `run_windows.bat`. Первый запуск ставит библиотеки (несколько минут, нужен интернет), потом открывается страница `http://127.0.0.1:5500`.

**macOS и Linux:** `sh run_linux_mac.sh`

**Вручную:**

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows;  на macOS и Linux:  source .venv/bin/activate
pip install -r requirements.txt
python tools/make_samples.py      # 12 учебных снимков + 1 настоящий в data/incoming
python app.py                     # интерфейс оператора
```

Обученная сеть уже лежит в `models/cloud_net.npz`, обучать её перед первым запуском не нужно.

## Три способа работы

| Что | Команда | Для чего |
|---|---|---|
| Интерфейс оператора | `python app.py` | Загрузить снимки, увидеть проценты, маски облаков и сообщение оператору; разметить свои снимки и дообучить сеть |
| Командная строка | `python process.py` | Обработать папку `data/incoming` без браузера |
| Пробный запуск | `python process.py --dry-run` | Только посчитать проценты, файлы не трогать |
| Корзина вместо удаления | `python process.py --trash` | Облачные снимки переносятся в `data/trash` |
| Другой порог | `python process.py --threshold 60` | Отсеивать при облачности выше 60 % |
| Автотесты | `pytest -q` | 44 проверки: логика, файлы, интерфейс |
| Проверка качества | `python evaluate.py` | Отчёт `reports/quality_report.html` с цифрами и картинками (2–5 минут) |
| Обучение | `python train.py` | Обучить сеть заново (1–3 минуты) |

**Осторожно с удалением.** По условию кейса облачные снимки стираются насовсем. Кладите в `data/incoming` копии снимков, а пока проверяете сеть, выбирайте режим «Переносить в корзину».

## Как выполнены требования кейса

| Требование | Где сделано |
|---|---|
| Алгоритм ИИ распознаёт процент облачности на снимке | Нейросеть в `cloudai/net.py`: для каждого пикселя — вероятность облака; процент = доля облачных пикселей |
| При облачности выше 75 % снимок отсеивается и удаляется | `cloudai/pipeline.py`, функция `should_delete`; ровно 75 % — ещё сохраняем |
| Сообщение оператору: имя сохранённого файла | Раздел «СОХРАНЁННЫЕ ФАЙЛЫ» сообщения |
| Сообщение оператору: процент облачности | Рядом с каждым файлом, с одним знаком после запятой |
| Сообщение оператору: имя удалённого файла | Раздел «УДАЛЁННЫЕ ФАЙЛЫ» сообщения |
| Обучение на снимках | Вкладка «Разметка и дообучение» и `python train.py` |

Сообщение показывается на странице и в консоли и сохраняется в `reports/` в трёх видах: текст, таблица CSV (открывается в Excel), JSON.

## Что проверено и чего ожидать

Проверка `python evaluate.py` на 300 учебных снимках, которых сеть не видела при обучении:

| | Нейросеть | Простое правило «яркий = облако» |
|---|---|---|
| Средняя ошибка процента облачности | 1,6 п.п. | 7,4 п.п. |
| Верных решений «сохранить / удалить» | 99,0 % | 95,0 % |
| Хороших снимков удалено по ошибке | 1 из 225 | 6 из 225 |
| Облачных снимков оставлено по ошибке | 2 из 75 | 9 из 75 |

Важные оговорки:

- **Это нарисованные программой снимки.** Снимки Спутникса получить не удалось: сайт с ними закрыт для автоматического скачивания. Поэтому базовая сеть обучена на снимках из генератора (`cloudai/synth.py`) и на снимках Спутникса не проверялась.
- **Снег и лёд сеть принимает за облака.** На снежных учебных снимках средняя ошибка 15 п.п., облачность завышается; 8 из 66 хороших снежных снимков были бы удалены. На обычной цветной фотографии белый снег и белое облако почти неразличимы.
- **Полупрозрачную дымку сеть не считает облаком.** На единственном настоящем снимке (Sentinel-2, `data/real_check`) сеть насчитала 27 % облачности, эталонный алгоритм s2cloudless — 46 %: плотные и кучевые облака найдены, дымка нет. Эталон видит 10 спектральных каналов и расширяет облака с запасом, так что это сравнение двух алгоритмов, а не проверка по истине.
- Тёмные снимки занижают облачность на 4–5 п.п., пересвеченные завышают примерно на 3 п.п.

Подробности и картинки — в `reports/quality_report.html`.

## Снимки Спутникса: что сделать в первую очередь

1. Скачайте снимки по ссылке из кейса: <https://disk.sputnix.ru/index.php/s/HbkKc34batcjkSX> или из канала <https://t.me/sputnixru>.
2. Положите копии в `data/incoming` и запустите `python process.py --dry-run`. Файлы не изменятся, вы увидите проценты.
3. Найдите снимки, где сеть ошиблась сильнее всего. Скопируйте 10–20 таких снимков в `data/real`.
4. Запустите интерфейс, откройте вкладку «Разметка и дообучение». Включите «Показать, что видит сеть» и проведите кистью: красным по облакам, которые сеть пропустила, синим по местам, которые она зря закрасила (снег, песок, блики).
5. Нажмите «Сохранить разметку», затем «Дообучить сеть». Если стало хуже — «Вернуть базовую модель».
6. Если к снимкам прилагаются готовые маски облаков, положите их в `data/masks` (белое — облако): они пойдут и в обучение, и в проверку качества.

## Устройство проекта

```
cloud-detector/
├── app.py               веб-интерфейс оператора (FastAPI)
├── process.py           обработка папки из командной строки
├── train.py             обучение сети
├── evaluate.py          проверка качества, отчёт с картинками
├── cloudai/
│   ├── imageio.py       чтение снимков (JPG, PNG, TIFF, BMP, WEBP; 8 и 16 бит)
│   ├── features.py      14 признаков каждого пикселя, поиск чёрных полей «нет данных»
│   ├── net.py           нейросеть 14 → 32 → 16 → 1 на чистом numpy
│   ├── synth.py         генератор учебных снимков с масками облаков
│   ├── training.py      сбор примеров и подбор весов
│   └── pipeline.py      процент, решение, перенос и удаление файлов, сообщение оператору
├── static/              страница интерфейса (HTML, CSS, JavaScript)
├── models/              cloud_net.npz — веса сети; cloud_net_base.npz — запасная копия
├── data/                incoming, saved, trash, real, labels, masks, real_check
├── tests/               автотесты
├── tools/make_samples.py  учебные снимки для пробы
└── reports/             отчёты
```

Нейросеть при работе использует только numpy и scipy. Библиотека scikit-learn нужна лишь для обучения. Интернет после установки не нужен: сервер работает на адресе `127.0.0.1`, снимки никуда не отправляются.

## Для преподавателя

### План занятий

Число занятий — ориентир, по 60–90 минут.

| № | Тема | Что делают ученики | Результат |
|---|---|---|---|
| 1 | Задача и первый запуск | Запускают интерфейс, обрабатывают учебные снимки, сравнивают проценты со своей оценкой на глаз | У всех работает; понятно, что требует кейс |
| 2 | Как компьютер видит снимок | Читают `features.py`, считают признаки одного пикселя вручную, пробуют простое правило «яркий = облако» | Понимают, зачем нужны признаки и почему одной яркости мало |
| 3 | Нейросеть и обучение | Читают `net.py` (три строки формул), запускают `train.py`, меняют размер сети и число снимков | Могут объяснить, что такое веса и обучение |
| 4 | Проверка качества | Запускают `evaluate.py` и `pytest`, разбирают отчёт: ошибки, ложные удаления, снег | Умеют читать метрики и называют слабые места |
| 5 | Настоящие снимки | Скачивают снимки Спутникса, размечают трудные, дообучают сеть, сравнивают «до» и «после» | Сеть, настроенная под реальные данные |
| 6 | Свой эксперимент и защита | Выполняют один опыт из GUIDE_RU.md, готовят демонстрацию и рассказ | Готовое выступление |

### Роли в команде из трёх человек

- **Исследователь данных:** собирает снимки, размечает, ищет ошибки сети.
- **Инженер модели:** обучение, признаки, опыты с настройками, отчёт о качестве.
- **Разработчик интерфейса:** страница оператора, сообщение, удобство работы, демонстрация.

### Что показать на защите

1. Обработку папки со снимками в интерфейсе: проценты, маски облаков, сообщение оператору.
2. Отчёт о качестве: цифры «до» и «после» дообучения на снимках Спутникса.
3. Честный список ограничений (снег, дымка) и что команда с ними сделала.
4. Один собственный опыт и вывод из него.

### Чем это решение отличается от «чёрного ящика»

Весь путь от пикселя до решения открыт и помещается в несколько небольших файлов с комментариями на русском. Ученик может изменить любое звено — признак, размер сети, порог, генератор — и сразу увидеть в отчёте, стало лучше или хуже.

## Частые проблемы

| Что видно | Что делать |
|---|---|
| `python` не найден | Установите Python с python.org, при установке отметьте «Add Python to PATH» |
| Страница не открывается | Проверьте, что окно с `python app.py` не закрыто; адрес `http://127.0.0.1:5500` |
| «Модель не найдена» | Запустите `python train.py` |
| Порт 5500 занят | `python -m uvicorn app:app --port 8010` и адрес `http://127.0.0.1:8010` |
| После дообучения стало хуже | Кнопка «Вернуть базовую модель» или скопируйте `models/cloud_net_base.*` поверх `models/cloud_net.*` |
| В консоли Windows вместо русских букв значки | Выполните `chcp 65001` перед запуском |
| Процент завышен на снежном снимке | Это известное ограничение; разметьте такие снимки синей кистью и дообучите сеть |
